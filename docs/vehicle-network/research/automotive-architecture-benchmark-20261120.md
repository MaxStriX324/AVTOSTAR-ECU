# Исследование автомобильных E/E-архитектур для AVTOSTAR — 20.11.2026

**Контекст:** пользователь переоценивает необходимость отдельного CLUSTER. Вариант для изучения: объединить кабельные входы водителя, измерение моторных сигналов, интерфейс штатных приборов и межсетевой Gateway в одном переднем корпусе, возможно с **двумя отдельными STM32F405**. Унифицированные силовые платы BCM-F/R-OUT сохраняются.

**Это исследование / сравнение, не утверждённый аппаратный проект.** Источники различаются по надёжности, лицензионным условиям, доступности файлов и сходству с ПАЗ-3206 2001 года.

## 1. Исторические и серийные архитектуры

| Реальная система | Доказанная структура | Что перенять / чего не выводить из источника |
| --- | --- | --- |
| **VW Golf/Jetta** | Отдельно J285 instrument cluster, J519 vehicle electrical system control module, J533 data bus diagnostic interface/gateway | Отделение функций и понятная диагностика, но это **не** означает, что три платы обязательны для проекта небольшой серийности. [Пример схемы VW Golf](https://charm.li/Volkswagen/2010/Golf%20%285K1%29%20L5-2.5L%20%28CBUA%29/Repair%20and%20Diagnosis/Diagrams/Electrical%20Diagrams/Automatic%20Transmission%2FTransaxle/Diagram%2047%2F9%20%28Tracks%2099-112%29/). |
| **Volvo V70/XC90 того поколения** | CEM = центральная электроника, REM = rear electronic module, DIM = driver information module, по CAN | Ближе к нашему физическому делению передней и задней зон. Контрольная конфигурация вариантов оснащения: один HW может применяться с разными параметрами. [Описание распределения функций CEM/DIM/REM (Volvo V70)](https://charm.li/Volvo/2003/V70%20T5%20L5-2.3L%20Turbo%20VIN%2053%20B5234T3/Repair%20and%20Diagnosis/Testing%20and%20Inspection/Programming%20and%20Relearning/Software%20Downloading/History/). |
| **BMW FEM/BDC** | В заводском учебном описании BMW G12 ZGM (центральный Gateway) **интегрирован внутрь** Body Domain Controller и логически ведёт себя как самостоятельный блок. BDC управляет кузовными функциями/электропитанием. [BMW G12 technical training, p. 34 (HTML)](https://www.manualslib.com/manual/2463678/Bmw-G12-2015.html?page=34), [BMW G30 body controller](https://www.bmw5g30.com/gateway-1872.html). | **Самый близкий прецедент** для корпуса с отдельным Gateway-контроллером. Источник НЕ доказывает, что ZGM имеет ровно два MCU STM32 либо что серийная BMW включает приборный щиток и аналоговые датчики двигателя в BDC. |
| **Современная zonal E/E** | Локальные физические зоны агрегируют ближайшие датчики, нагрузки и питание, центральная сеть связывает их | Сохраняем **унифицированную плату BCM-F/R-OUT**, уменьшаем длинные силовые жгуты и каналы одной высокой мощности. [NXP Automotive Zone Controller](https://www.nxp.com/applications/AUTOMOTIVE-ZONE-CONTROLLER), [NXP Gateway](https://www.nxp.com/applications/GATEWAY). |

**Промежуточный вывод:** физический центральный узел «ввод кабины + Gateway» хорошо обоснован примерами BMW; «приборы + датчики карбюраторного двигателя + этот же блок» — кастомный вариант, требующий отдельного сравнения ремонтопригодности, длины датчиковых линий и отказов. OEM-факт и наша рекомендация не одно и то же.

## 3. Архитектурные уроки для AVTOSTAR

1. **Физический корпус ≠ один ECU.** OEM интегрируют Gateway внутрь кузовных модулей, сохраняя логическое разделение маршрутизации и локального управления.
2. **Одно программное ядро для всего нежелательно**, если его сбой одновременно отключит приборы, кнопки и обмен между ENGINE/BODY/HOUSE.
3. Приборная панель с существующими проводными аналоговыми шкалами не требует отдельного CAN-ECU **уже сейчас**. Для первого этапа сохранить штатный спидометр/двухстрелочный манометр/аналоговые приборы/аварийные индикаторы.
4. **Скорость CAN не главный аргумент прямого подключения CLUSTER к ENGINE.** Корректно настроенный Gateway пересылает кадры быстро; ключевой вопрос — доступность данных при его отказе и исключение зависимости критической индикации от сети.
5. Если центральный передний ECU измеряет аналоговые датчики двигателя, это **не** обязательно означает хороший выбор для длинных/грязных чувствительных линий. Ресурс проводки и помехи решают, ставить ли компактный удалённый моторный I/O.
6. Заимствование исходного кода/PCB из GitHub требует отдельной проверки лицензии и реальных испытаний, особенно если AVTOSTAR планируется как коммерческий продукт.

## 4. Необходимая следующая работа перед схемами

- Инвентаризировать реальную панель ПАЗ 2001: [фоторазбор](../paz-2001-dashboard-photo-inventory.md) и задние соединения.
- Измерить расстояния кабелей до RPM, VSS1 раздатки, VSS2 КПП, ОЖ, давления масла, топливного бака; составить карту источников помех.
- Составить полный I/O budget под один front cockpit MCU и проверить распиновку STM32F405 LQFP100/144, DMA/таймеры/CAN/ADC/SPI/USB/SWD.
- Выбрать сценарий отказа двух MCU, по очереди выключить MCU A, MCU B и каждый преобразователь питания.
- Отдельно спроектировать аппаратный резерв стоп-сигналов, аварийки, аварийного выключателя и основных предупреждений; не выводить safety-решение из учебных примеров.
- Договориться о протоколе: кто **производит** RPM/VSS/температуру, где единственный источник истины, что будет при будущей установке ECU.
- Проверить доступность компонентов и классы automotive transient protection 12/24 В до PCB.

[Альтернативы интеграции и proposed architecture](../rfc-integrated-front-cockpit-20261120.md).

## 5. Статус

**Предварительное предпочтение:** один передний сервисный корпус с двумя независимыми контроллерами, совмещающий Switch-IN, интерфейс исходных приборов и наблюдение за датчиками двигателя (по длинам проводов), а также отдельный сетевой Gateway. Передний и задний силовые BCM остаются одной PCB. Отдельный CLUSTER — **альтернатива, не утверждённое решение**.

# Топология CAN, блоки и потоки сигналов

## Логическая схема

~~~text
                        AVTOSTAR Gateway (STM32F405 + ESP32)
                        CAN1 | CAN2 | SPI-CAN3 | SPI-CAN4
                          |      |       |         |
                    ENGINE    BODY     HOUSE    AUX/SPARE
                       |        |        |
             ECM-IO / ECU     BCM-F-IN  HOUSE-IO
             TCU / Hybrid     BCM-F/R-OUT Climate / Power
             Cluster          Accessories Sensors
~~~

Каждая шина — отдельный физический сегмент с собственным CAN-трансивером и терминаторами на концах линии. Классическая линейная топология предпочтительна ответвлениям-звёздам; длины ответвлений и скорости валидируются измерениями. При наличии штатных CAN автомобиля взаимодействие допускается только после анализа их протоколов.

## Назначение блоков

| Узел | CAN | Роль |
| --- | --- | --- |
| BCM-F-IN | BODY | Кнопки, подрулевые переключатели, замок как информационные входы |
| BCM-F-OUT | BODY | Передняя оптика, боковые передние габариты, сигнал, защищённый интерфейс дворников |
| BCM-R-OUT | BODY | Задние фонари, боковые задние габариты, номер, верхняя светотехника |
| ECM-IO | ENGINE | Датчики двигателя, трамблёр, генератор, VSS, вспомогательные выходы |
| AVTOSTAR ECU | ENGINE | Отдельный ECU для впрыска, зажигания и моторных датчиков — будущий узел |
| TCU / Hybrid | ENGINE либо отдельный AUX | Собственные силовые контроллеры с независимыми защитами |
| Gateway | Все 4 физически | Списочная маршрутизация, диагностика, журнал, интерфейс ESP32 |
| HOUSE-IO / HOUSE-POWER | HOUSE | Салон, насосы, климат, датчики баков, АКБ автодома, сеть |

## Назначение четырёх контроллеров Gateway (предварительно)

| Порт | Реализация | Назначение |
| --- | --- | --- |
| CAN1 | bxCAN STM32F405 | ENGINE CAN |
| CAN2 | bxCAN STM32F405 | BODY CAN |
| CAN3 | MCP2518FD по SPI | HOUSE CAN |
| CAN4 | MCP2518FD по SPI | AUX / будущая отдельная сеть трансмиссии или гибрида |

CAN2 в STM32F405 использует общие ресурсы bxCAN и требует тактирования CAN1; это не четыре аппаратно независимых процессора. У каждого интерфейса должен быть свой трансивер. Внешние MCP2518FD потенциально позволяют CAN FD, но встроенные bxCAN не поддерживают CAN FD; прямая прозрачная ретрансляция FD-кадров в классический CAN невозможна.

## Принципы работы

- Все BCM должны обрабатывать локальные входы/выходы без участия Gateway там, где это возможно.
- BODY-сеть сама обслуживает освещение; логика кузова не зависит от HOUSE или ENGINE.
- Gateway пересылает только разрешённые сигналы и не превращается в бесконтрольный CAN-мост.
- ECU получает непосредственно все необходимые для управления двигателем датчики; ECM-IO не является обязательным посредником.
- HOUSE CAN может считывать двигатель и энергию только через разрешённые сообщения; никакого произвольного управления мотором.
- ESP32, Wi-Fi, HTTP и внешние сервисы не участвуют в критических контурах и не должны останавливать другие функции.

## Монтаж и питание

Силовая магистраль может идти от защищённой распределительной точки к заднему блоку; ветви снабжаются предохранителями у источника и локально, если нужно. Масса, падение напряжения, токи пуска и худшие режимы рассчитываются по схеме реального автобуса. CAN-проводка прокладывается отдельно от силовых коммутационных линий там, где это необходимо для EMC.

# Аудит архитектуры AVTOSTAR Vehicle Network — v1

**Дата:** 2026-11-19. **Объект:** первый экземпляр — ПАЗ-3206, 2001 год, бензиновый карбюратор/трамблёр, 12 В, механический спидометр с приводом на раздатке, без ABS, пассажирский электропривод двери отсутствует (заменена аварийной дверью).  
**Статус:** архитектурное предложение на ревью, **не** готовая схема подключения. См. [инвентаризацию приборов](instrument-cluster-audit.md) и [матрицу сигналов](signal-matrix-v1.md).

## Основание: реальная панель ПАЗ-3206 по фотографиям

После исходного аудита владелец предоставил четыре снимка панели. Внешне подтверждены механический спидометр, **один комбинированный круглый прибор** с пятью шкалами (центральный пневмоманометр двухстрелочный), девять цветных сигнальных окон, визуально 11 клавиш, отдельный аварийный выключатель с фиксатором и отдельная кнопка аварийки. Уточнённый [протокол внешней инвентаризации](paz-2001-dashboard-photo-inventory.md). Для первого этапа CLUSTER нельзя понимать как обязательную физическую замену действующих приборов.

## 1. Итог аудита

Оставить физически отдельные ENGINE, BODY, HOUSE CAN, а также резервную CAN4 у Gateway. Важно добавить **AVTOSTAR CLUSTER** в число самостоятельных блоков: только Gateway/ESP32 — недостаточно для автономной приборной панели. CLUSTER должен иметь два CAN (ENGINE и BODY) только для получения состояния; **не** образует второй межсетевой шлюз. Требуемые независимые сигнальные лампы/приборы функционируют без Gateway и CAN по отдельным штатным или проверенным аппаратным трактам.

Для нынешнего ПАЗ необходимо разделять:
- подтверждённые владельцем особенности машины (2001/12 В/нет ABS/нет привода двери);
- заводские сведения **более поздней** модификации ПАЗ-3206-110 (руководство 2012 г.);
- схемы бензинового ПАЗ-32053 2012 г. и каталог приборов ПАЗ-32053 2004 г. (родственная модель, не доказанная распиновка ПАЗ-3206 2001);
- схемы ПАЗ-320405/320445 Vector NEXT (другая платформа/поколение, в том числе цепи 24 В).

Нельзя принимать чужую распиновку или состав ламп/датчиков за реальную заводскую проводку автобуса 2001 года.

## 2. Рекомендуемая логическая топология

~~~text
                АКБ 12 В / генератор (для платформы — номинальные 12/24 В)
                                 |
                  POWER DISTRIBUTION (локальные предохранители)
                   |                 |                 |
          передний электрощит   моторный отсек    задний электрощит
                   |                 |                 |
 ENGINE CAN ----- ECM-IO -------- будущий AVTOSTAR ECU ------[CLUSTER: ENGINE CAN/RX]
       |                |                            (локальные моторные сигналы)
       +--------- Gateway STM32F405: CAN1/2 + 2xSPI-CAN ---------------+
 BODY CAN ------- BCM-F-IN --- BCM-F-OUT --- BCM-R-OUT ----[CLUSTER: BODY CAN/RX]
       |
 HOUSE CAN ------ HOUSE-POWER/HOUSE-IO --- CLIMATE/WATER/SENSORS
       |
 AUX CAN (четвёртый порт Gateway, назначение не утверждено)

 CLUSTER = индикация/показометры/контроль ламп/дополнительная диагностика;
           критические предупреждения отдельными аппаратными линиями.
~~~

Здесь линии ENGINE/BODY физически не объединены через CLUSTER — у CLUSTER два отдельных трансивера и независимые CAN-контроллеры, пересылка кадров и управляющих команд **запрещена**. Gateway выполняет единственную штатную межсетевую маршрутизацию по whitelist. HOUSE никогда не предоставляет произвольного управления мотором, тормозами и наружным светом.

## 3. Кто за что отвечает

| Блок | Входы | Выходы / обязанности | Что **не** делает |
| --- | --- | --- | --- |
| BCM-F-IN (кабина) | Свет, указатели поворота, аварийная, дворники, омыватель, сигнал, переключатели отопителя/обдува, замок IGN/START как статус, дополнительные выключатели | Публикует положения и исправность органов управления в BODY CAN; аппаратные независимые резервные линии важных команд | Не является трёхшинным Gateway, не коммутирует стартер или цепь зажигания только через CAN |
| BCM-F-OUT (передний электрощит) | BODY CAN, локальные резервные линии и контроль напряжения | Ближний/дальний слева/справа, передние/боковые габариты, передние повороты, ДХО/ПТФ при наличии, сигнал, омыватель; управление дворниками специальным взаимоблокированным каскадом | Не принимает ответственность за двигатель, приборный щиток или тормозную систему |
| BCM-R-OUT (задняя часть) | BODY CAN, прямой резерв тормоза, возможно сигнал заднего хода; локальное питание | Стопы левый/правый, задние повороты, габариты, номер, верх/боковые группы, задний ход/ПТФ; диагностирует обрыв, ток и short | Не зависит **только** от Gateway/CAN для стопов; не управляет двигателем |
| ECM-IO (моторный отсек/трансмиссия) | RPM с защищённого формирователя; VSS раздатки/КПП; давление масла, температура ОЖ, уровень/состояние зарядки, аварийные моторные контакты; возможные датчики переднего моста, сцепления, заднего хода | Измеряет/калибрует, сообщает ENGINE CAN, генерирует нужный частотный выход старому тахометру; может управлять **вспомогательными** реле при отдельной проверке | Не становится посредником критических ДПКВ/ДПРВ для будущего ECU; не подменяет штатные аппаратные предупреждения |
| AVTOSTAR ECU (будущее) | Свои непосредственные датчики двигателя и синхронизации | Впрыск, зажигание, расчёт RPM/нагрузки, диагностика; ENGINE CAN | Не зависит от ESP32/Gateway/CLUSTER для работы двигателя |
| AVTOSTAR CLUSTER (новый) | ENGINE CAN (RX) + BODY CAN (RX), локальные 12/24 В через защиту, аппаратные сигналы предупреждения, сервисные линии | Аналоговые/цифровые приборы и индикация, диагностика обрывов сообщений; собственный дисплей при желании, подсветка и тест ламп | Не передаёт ENGINE↔BODY кадры; не блокирует двигатель/тормоза; не заменяет аварийную независимую сигнализацию |
| Gateway | ENGINE, BODY, HOUSE, AUX CAN; ESP32 | Whitelist маршрутизация, журнал ошибок, объединённая диагностика, конфигурации/обновления в сервисном режиме | Не нужен для обычной работы приборов, стопов и моторных датчиков |
| HOUSE-IO / HOUSE-POWER (позднее) | Датчики воды, баков автодома, климата, аккумуляторов | Свет жилой части, водяные насосы, бытовой климат, резервное питание, мониторинг | Не подменяет водительский обдув/обеззапотевание и другую эксплуатационно важную кузовную систему |
| PDU / блоки питания (перед/зад) | АКБ, генератор, IGN | Отдельные защищённые магистрали и ветви к потребителям, штатные/расчётные предохранители | Не заменяется одним общим электронным предохранителем без селективности |

**Варианты PCB:** F-OUT и R-OUT — одна плата и прошивка, до 24 выходов как проектная цель, частичная комплектация DNP по профилю авто. У ECM-IO и CLUSTER возможно общее STM32F405 CORE, но их аналоговая и сигнальная периферия различна. Для Gateway STM32F405 2 bxCAN и 2 внешних SPI-CAN (MCP2518FD кандидат).

## 4. Проверка архитектуры по неисправностям

| Отказ | Требование |
| --- | --- |
| Gateway выключен | CLUSTER напрямую читает ENGINE/BODY; локальные BODY блоки продолжают работу |
| Один CAN-канал CLUSTER потерян | Данные с этого канала становятся INVALID; остальные источники/аппаратные контрольные лампы продолжают работу |
| ESP32/веб-сервис завис | Наружное освещение, мотор, приборы и критические лампы не затрагиваются |
| ECM-IO отказал | ECU при наличии продолжает управлять двигателем независимо; аппаратная аварийная индикация сохраняется; потерянные телеметрические показания помечены отсутствующими |
| BCM-R потерял питание | Независимая цепь стопов обеспечивает функциональность после **отдельного анализа и испытания**, простой дополнительный контакт на MCU для этого недостаточен |
| Пропал сигнал уровня топлива | Показывать отсутствие данных, не ноль; не создавать ложный «пустой бак» |
| Нет VSS | Скорость/передача становятся недостоверны; подсказки переключения запрещаются |
| Вышел из строя CAN/MCU | Аварийные световые приборы и предупреждения, требующие резервирования, работают через независимый проверенный тракт |
| Неустановленный DNP выход | Профиль HW это обнаруживает, SW не разрешает включать канал |

## 5. Технические ограничения, выявленные аудитом

1. **Не определён состав реальной приборной панели 2001 года.** Нужны фото лица/обратной стороны и реальная схема ПАЗ-3206/3205 соответствующей редакции.
2. **Нужны два уровня безопасности индикации.** CAN-диагностика вторична, масло/температура/тормоза/зарядка требуют проверки сохранённых аппаратных трактов; для остальных сигналов разумен CAN.
3. **Питание 12/24 В** требует профилей защиты по транзиентам, различающихся номиналов нагрузок и недопустимости прямого подключения 12-В стрелочных приборов к 24 В.
4. **Не все датчики можно параллельно подключать к старым стрелочным приборам.** Некоторые реостатные датчики работают с конкретным током возбуждения; для мониторинга нужны высокоомные буферы и индивидуальная калибровка либо отдельные датчики.
5. **Генератор D+/61** может участвовать в возбуждении и штатной лампе. Нельзя разрывать эту цепь ради измерения; сначала установить схему генератора и регулятора.
6. **Влажность/вибрация/нагрев:** зоны размещения блоков, автомобильные разъёмы, защита входов и драйверы с индуктивными нагрузками требуют самостоятельного проектирования.
7. **Локальная работа BODY:** переключатель аварийки и стопы не должны зависеть только от многоузлового CAN; независимые линии и аппаратное резервирование требуют отдельной схемы.
8. **Передаточные числа 1.000/1.982** приводятся в руководстве ПАЗ-3206-110 2012 года и не доказаны для раздатки 2001 года.
9. **Автодом:** при разделении HOUSE и BODY водительское отопление/обдув стекла относится к BODY, бытовой климат — к HOUSE. Физическое отопление может иметь общие трубопроводы, но исполнительные цепи и режимы безопасности нужно разделить.

## 6. Решения для следующего ревью

- ADR-PROPOSED-CLUSTER: добавить CLUSTER как отдельный узел с 2 RX-only CAN (ENGINE/BODY) и локальными аппаратными предупреждениями.
- ADR-PROPOSED-SENSORS: определить по каждому датчику режим первичного подключения: штатный напрямую; высокоомный параллельный монитор; или новый цифровой датчик/контроллер.
- ADR-PROPOSED-TELLTALES: для дальнего света, поворотников и габаритов подтверждать **фактическую работу выходов**, а не только запрос переключателя.
- ADR-PROPOSED-PHASES: фаза A — сохранить приборы, наблюдать/логировать; B — собственная CAN-панель; C — электронный спидометр и дополнительные функции трансмиссии.

## Источники и степень достоверности

- Владелец: ПАЗ-3206, 2001 г., 12 В, без ABS, без электропривода пассажирской двери, карбюратор, механический тросовый спидометр (подтверждено для данного авто).
- Загруженное `avtobus_paz_3206110 (1).pdf`: дополнение 2012 г., раздатка/тормоза, не схема 2001 года.
- Загруженное `электросхема паз.pdf`: ПАЗ-320405-04/320445 Vector NEXT, **другая модель**; PDF стр. 4–6 и 8–13 полезны только как перечень функциональных цепей.
- [ПАЗ-32053, руководство по эксплуатации (2012)](https://rusautobus.ru/pdf/paz-32053.pdf) — более поздний бензиновый ПАЗ; не использовать распиновку без сверки.
- [Каталог ПАЗ-32053, щиток с гибким валом](https://www.katalogionline.ru/avtobusy-paz/paz-32053/shitok-i-kombinaciya-priborov-s-gibkim-valom-128) — подтверждает классы/артикулы приборов, но не точную комплектацию 2001.
- [ПАЗ-32053-07/4234, рис. 7-6 лист 11](https://rusautobus.ru/pdf/paz-32053-07-4234.pdf) — дизельная родственная модификация, позволяет различать указатели, лампы и схемные связи.
